# Панель — дисциплина проверки (скилл для Claude Code и Codex)

Скилл (навык) для [Claude Code](https://claude.com/claude-code) и совместимых агентов
(Codex, Cursor, Gemini). На важной задаче он включает **короткий обязательный проход
проверок**, прежде чем дать ответ: сверить факты с первоисточником, задать вопросы к данным,
пропустить через критика — и выдать короткий вывод с названными рисками.

Честно о названии: это **не восемь независимых экспертов, которые спорят**. Это один процесс
с чек-листом. Строгость даёт не театр ролей, а проверка источников, вопрос «что бы это
опровергло» и скучный сверочный проход. Роли (линзы) — лишь углы, под которые прогоняешь
задачу, когда они меняют вывод. Решения на ИИ-агентах предлагаются первыми, классические — вторыми.

Задуман для реальных задач непрограммиста: развитие бизнеса, маркетинг, выбор ниши, клиентские
тексты, оценка идеи, «что делать дальше». На мелочи (правка, факт, одна команда) проход не
включается, чтобы не жечь токены.

## Что он реально делает

1. **Проверка фактов до выдачи.** Каждое фактическое утверждение → первоисточник (файл,
   страница меню, сайт). Нет источника — утверждение вылетает. Первичное бьёт вторичное; в
   длинном диалоге — перечитать документы, а не доверять памяти.
2. **Вопросы к данным сначала.** До текста — 3-5 вопросов, ответы на которые изменят вывод, и
   поход за ответами. Отвечает на вопрос, от которого зависит результат, а не только на заданный.
3. **Критик до написания.** Называет, что скорее всего ложно и какой вопрос не задан, — и это
   блокирует выпуск, а не украшает готовое.
4. **Коротко и с рисками.** Длинный текст прячет ошибку. Вывод короткий, риски названы.
5. **AI-first.** Сначала как задачу закрыть ИИ-агентом (бот-квалификатор, автосбор отзывов,
   инструмент-калькулятор), потом классика — с проверкой «а не театр ли это»: сколько стоит,
   кто чинит, не проще ли человек.
6. **Проверка спроса перед продуктом.** Прежде чем строить продукт или услугу — маркетолог
   смотрит реальный спрос (Вордстат/Google) и главный тест: продаёт ли это кто-то платно.
   Базовая проверка — авто; полный маркетинг-аудит — по вашему согласию, дорогой по токенам
   (скажите «полный маркетинг-аудит», «маркетинг по полной» или `/аудит`).
7. **Разведка перед сложной работой.** Навык `scout` в комплекте: как задачу уже решили в мире
   и какие есть готовые навыки ИИ (каталог Anthropic, GitHub, skills.sh) — с автопроверкой чужих
   навыков на вшитые команды. Не изобретать велосипед.

## Как это выглядит

Вы задаёте вопрос. На важной задаче агент идёт по чек-листу:

```
1. Вопросы к данным   → что нужно узнать, чтобы ответ был верным — и находит ответы
2. Первоисточники     → каждый факт со ссылкой на источник; нет источника — вылетает
3. Критик до текста   → что скорее всего ложно, какой вопрос не задан (блокирует выпуск)
4. Черновик коротко   → длина прячет ошибки
5. Сверка построчно   → каждое утверждение → где проверено
6. Вывод и риски      → коротко, риски названы; план важной работы — на ваше «делай»
```

Отдельно защищён текст для клиента (рассылка, пост, оффер): два гейта — ценность клиенту И
выгода бизнесу — плюс критик, прежде чем показать. Проверка включается на каждое новое важное
задание в беседе, а не только в начале.

**Сортировка — в любой момент диалога.** Каждое новое задание сначала относится к размеру — бесплатно,
без действий. Мелкое (вопрос, правка, расчёт, «дальше») — сразу ответ, без согласований. Среднее — одно
сообщение «понял так, сделаю так». Крупное (исследование, стратегия, план, сайт, агент, набор клиентских
текстов, деньги) — первым ответом только понимание задачи, цель и 2–4 вопроса, без поиска; дальше цель →
короткая разведка → план → требования на один экран → работа, с вашим одобрением на каждом шаге. Так же и
через двадцать сообщений: новое крупное задание снова начинается с цели.

## Установка

Нужен агент, понимающий скиллы (`SKILL.md` — открытый стандарт). Пример — [Claude Code](https://docs.claude.com/en/docs/claude-code):

```bash
git clone https://github.com/AnDeulin/panel.git ~/.claude/skills/panel
```

Это всё — скилл уже работает. В новом диалоге задайте важный вопрос, и проверка включится сама.
Или позовите вручную: `/panel`, `/panel quick`, `/panel full`.

### В Codex, Cursor и других агентах

Тот же скилл работает в Codex CLI, Cursor, Gemini и других — формат `SKILL.md` общий для всех.
Отличается только папка, куда клонировать. Для Codex:

```bash
git clone https://github.com/AnDeulin/panel.git ~/.codex/skills/panel
```

Дальше так же: агент сам подхватит скилл и вызовет его по `/panel` или по фразе «собери панель».
Чтобы проверка включалась автоматически (без команды) на важные задачи и на каждый клиентский
текст, в любой момент беседы — добавьте строчку про вызов скилла `panel` в `~/.codex/AGENTS.md`
(у Codex это аналог `CLAUDE.md`).

### Разведчик (scout) — в комплекте

После установки панели скопируйте папку разведчика в навыки — одной командой:

```bash
cp -r ~/.claude/skills/panel/scout ~/.claude/skills/scout
```

Для Codex — то же из `~/.codex/skills/panel/scout` в `~/.codex/skills/scout`. Автопроверка чужих
навыков — `python scout/scripts/scan_skill.py ПАПКА`: только стандартный Python, ничего ставить не нужно.

### Напоминалка для долгих диалогов (по желанию, Claude Code на Windows)

В длинной переписке правила из начала диалога «тускнеют». Скрипт `hooks/triage-reminder.ps1` смотрит
каждое ваше сообщение: если видит признаки крупной задачи («исследуй», «стратегия», «план», «сайт»,
«агент»…), подкладывает агенту одну строку-напоминание рядом с сообщением. Нет признаков — ничего не
делает и токенов не тратит. Решение «мелкое или крупное» всё равно принимает агент.

1. Скопируйте `hooks/triage-reminder.ps1` в `~/.claude/hooks/`.
2. Добавьте в `~/.claude/settings.json`, в раздел `hooks`:

```json
"UserPromptSubmit": [
  { "hooks": [ { "type": "command",
    "command": "powershell -NoProfile -ExecutionPolicy Bypass -File C:/Users/ВАШЕ_ИМЯ/.claude/hooks/triage-reminder.ps1",
    "timeout": 10 } ] }
]
```

Путь — **с прямыми слэшами**: на Windows с Git Bash команды перехватчиков идут через bash, а он
«съедает» обратные слэши, и скрипт молча не находится. Признаки крупной задачи и текст напоминания
правятся прямо в скрипте; выключатель — `$enabled` в начале файла. Скрипт рассчитан на Claude Code;
в других агентах достаточно правила сортировки из раздела «Автозапуск».

### (по желанию) Настроить под себя

Скилл работает и без настройки, но с профилем проверяет точнее в ваших реалиях: ваше место и
ниша, что уже есть под рукой, что считаете успехом.

```bash
cd ~/.claude/skills/panel
cp reference/profile.example.md reference/profile.md
```

Откройте `reference/profile.md` и заполните под себя — хотя бы коротко: кто вы, город, ниша,
что уже есть из инструментов, что считаете успехом. Чем подробнее — тем точнее.

Файл `learned.md` (журнал ваших правок) создавать заранее не нужно: стартовые правила уже
встроены в скилл, а личные правила он начнёт записывать сам, когда они появятся. Оба файла в
`.gitignore` — остаются только у вас и в git не уходят.

## Команды

| Команда | Что делает |
|---|---|
| (ничего) | на важной задаче проверка включается автоматически |
| `собери панель` / `панель` | позвать вручную обычным языком |
| `/panel` | полный проход проверки |
| `/panel quick` | короткая проверка, второе мнение |
| `/panel full` | широкий поиск и бенчмарки под дорогое решение |
| `/panel tune` | ревизия самого скилла: обновить правила, предложить правки |

## Структура

```
SKILL.md                    ядро: когда включать, чек-лист проверки, гейты клиентских текстов, формат ответа
reference/roles.md          меню линз и составов (углы проверки, не труппа)
reference/marketing.md      маркетолог: базовая проверка спроса (авто) и полный аудит (по согласию)
reference/research.md       поиск и сверка источников, бенчмарки
reference/ai-first.md       каталог агентных решений + проверка на «ИИ-театр»
reference/tokens.md         экономия токенов в длинном диалоге
scout/                      навык-разведчик: как это уже сделали + готовые навыки ИИ, автопроверка навыков
hooks/triage-reminder.ps1   напоминалка о сортировке задания для долгих диалогов (по желанию)
reference/profile.example.md  образец профиля — копируется в profile.md (личный, не в git)
learned.example.md          образец журнала правил — копируется в learned.md (личный, не в git)
```

`SKILL.md` — единственный файл, который агент видит всегда (точнее, только его имя и описание,
~100 токенов). Остальное подгружается по мере надобности. Это [прогрессивная загрузка](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices):
скилл не занимает контекст, пока не понадобился.

## Как настроить под себя

- **Профиль** (`reference/profile.md`) — главное. Кто вы, где, чем занимаетесь, что уже
  есть под рукой, что считаете успехом.
- **Линзы** (`reference/roles.md`) — добавьте углы проверки и составы под свои задачи.
- **Ресурсы** (`reference/ai-first.md`, раздел «Инвентаризация») — впишите свои инструменты,
  чтобы скилл не предлагал строить то, что у вас уже есть.
- **Правила** (`learned.md`) — растёт сам из ваших правок; можно дописывать руками.
- **Автозапуск и сортировка** — добавьте в свой `~/.claude/CLAUDE.md` (или `~/.codex/AGENTS.md`)
  правило ниже. Оно грузится в каждый диалог и решает «мелкое или крупное» бесплатно — ещё до
  загрузки навыка.

```markdown
## Сортировка каждого задания — в любой момент диалога
Каждое новое задание сначала молча отнеси к размеру — без действий и чтения файлов:
- Мелкое — сразу ответ: вопрос, объяснение, факт, расчёт, правка, команда, отладка, следующий шаг
  уже одобренной работы. Навык panel не загружать.
- Среднее — одно сообщение «понял так, сделаю так», жди «делай».
- Крупное — навык panel: исследование, стратегия, план, сайт или лендинг, ИИ-агент или система, набор
  клиентских текстов, деньги, публичное. Первый ответ — только как понял, цель, 2–4 вопроса и что
  сделаешь после одобрения; до одобрения без интернета, разведки и помощников.
- Внутри долгого диалога — так же; в сообщении с целью перечисли, что уже договорено. Продолжение
  одобренной работы согласования не перезапускает.
- Сомневаешься — считай средним.
```

## На чём основано

Конструкция опирается на исследования мульти-агентных систем и официальные рекомендации по
скиллам, а не на догадки. В том числе поэтому здесь **нет** театра спорящих ролей:

- **Прогрессивная загрузка и структура скилла** — [Skill authoring best practices, Claude Docs](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices).
- **Почему «панель» деградирует как обсуждение** (факты вымываются, мнения сползают к общему) —
  «The Deliberative Illusion» ([arXiv](https://arxiv.org/pdf/2606.03032)). Отсюда отказ от ролевого
  спектакля в пользу проверки источников и сверочного прохода.
- **Дебаты дороги и по качеству спорны** — «Should we be going MAD?» ([ICML](https://openreview.net/pdf?id=CrUmgUaAQp)).
  Отсюда короткий проход и право не включаться на мелочи.
