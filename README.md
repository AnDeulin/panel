# Panel 3 — панель для агентных сред

Переносимый навык для сложных решений: **цель → бизнес-требования → план → реализация**.
Работает в начале и середине диалога, учитывает применимые прежние решения, исходники
проекта и изученные навыки. Простые задачи выполняются без панели.

## Режимы

| Режим | Когда | Кто работает |
| --- | --- | --- |
| Без панели | Простой вопрос, небольшая обратимая правка, обычное продолжение | Основной агент напрямую |
| `quick` | Ограниченная задача, где достаточно одного проверочного прохода | Один агент с обязательной функцией критика с начала |
| `full` | Несколько компетенций, существенная неопределённость или серьёзный риск ошибки | Ведущий и реальные отдельные агенты, включая отдельного критика с запуска |

Качество важнее экономии после запуска панели. Состав минимально достаточный, без
обязательной большой команды. Первые заключения — до просмотра ответов коллег;
далее один адресный раунд проверки существенных возражений. Дополнительная роль или
раунд нужны только для конкретного нерешённого вопроса. Согласие допустимо, спор
ради формата не требуется. Мнения одной модели могут разделять ошибки.

В основном чате: **состав и зачем → очень короткие существенные разногласия → общий
вердикт**. Источники и важные ограничения — рядом с выводом; подробные заключения
доступны по запросу. Это публичные обоснования, а не скрытая цепочка рассуждений.

## Внутри длинного диалога

Каждое новое задание оценивается коротким правилом в постоянных инструкциях среды:

- Простое — сразу выполнить без panel и её справочников.
- Продолжение одобренного плана — продолжать текущий этап, без повторных согласований.
- Новый сложный подвопрос той же цели — выбрать нужный режим и роли, используя
  действующие требования и уже проверенные факты.
- Новая сложная цель — сначала уточнить изменившееся и перенести применимые договорённости.

Для многоэтапной работы используется краткий паспорт задачи и индекс источников:
цель, требования, решения, этап, открытые вопросы, пути/ссылки, версии и даты проверок.
Они относятся к рабочему проекту, а не публичному репозиторию навыка. Источники и
справочники подгружаются выборочно; изменившиеся или устаревшие сведения перепроверяются.
Навык не гарантирует память всей истории, других чатов или недоступных файлов.
Подробнее: [контекст](reference/context.md), [необязательный образец](reference/task-passport.example.md).

## Установка из исходников

Нужен Python 3.9+ без дополнительных пакетов. Команды ниже запускаются **из клона
этого репозитория**; установщик не входит в устанавливаемые навыки.
На Windows вместо `python3` может использоваться `python`.

```bash
git clone https://github.com/AnDeulin/panel.git
cd panel
```

Установка для рабочего проекта; замените путь своим:

```bash
python3 scripts/panel_setup.py install --host codex --scope repo --project "/path/to/project" --instructions
python3 scripts/panel_setup.py install --host claude-code --scope repo --project "/path/to/project" --instructions
```

Выберите нужную среду; устанавливать обе необязательно. Для всех проектов пользователя
используйте `--scope user` вместо `--scope repo --project ...`.

Установщик:
- копирует только runtime-файлы panel и scout в папки выбранной среды;
- с `--instructions` добавляет короткий маркированный блок маршрутизации, сохраняя
  существующее содержимое `AGENTS.md` или `CLAUDE.md`;
- без этой опции инструкции не меняет: остаются явный вызов и обычный подбор навыка средой;
- отказывается перезаписывать чужую/изменённую установку и проходить через символические ссылки;
- повтор своей неизменённой установки выполняет без изменений.

Существующие старые копии не обновляются принудительно. Сначала сохраните личные
`reference/profile.md`, `learned.md` и свои настройки; проверьте отличия и осознанно
перенесите прежний каталог, прежде чем устанавливать новую копию. В старых постоянных
инструкциях удалите или согласуйте противоречащие правила о «линзах вместо агентов».
Личные файлы не копируются в новые установки автоматически.

## Подключение и совместимость

| Среда | Навыки проекта / пользователя | Явный вызов |
| --- | --- | --- |
| Codex app и CLI | `.agents/skills` / `~/.agents/skills` | `$panel quick`, `$panel full`, выбор из `/skills` или обычная фраза |
| Локальный Claude Code | `.claude/skills` / `~/.claude/skills` | `/panel quick`, `/panel full` или обычная фраза |
| Другие агентные клиенты | По документации клиента | По его механизму навыков/инструкций |

Общие фразы: «собери панель», «panel quick», «panel full». Явный вызов включает
панель даже на простом задании. Без режима выбирается минимально достаточный.
`/panel` не является универсальной встроенной командой всех клиентов.

Короткое правило маршрутизации находится в установщике и может быть добавлено явно
через `--instructions`. Оно действует на каждом новом задании и направляет к ядру,
не требуя загрузки всей библиотеки на каждое сообщение. Это инструкция модели,
а не гарантия безошибочного распознавания сложности; явный вызов остаётся резервным способом.

Адаптеры: [Codex](adapters/codex.md), [Claude Code](adapters/claude-code.md),
[другие среды](adapters/generic.md). Они задают подключение и использование реальных
инструментов; постоянные определения каждой возможной роли не обязательны.
`full` доступен только при фактическом запуске и получении результатов отдельных агентов.
Лимит параллельных агентов можно обработать очередью. Если делегирования нет,
панель сообщает ограничение и предлагает `quick`, не имитируя участников.

Подготовлены адаптеры Codex и Claude Code. Установка проверяется изолированными
локальными тестами; фактические автозапуск и делегирование проверяются отдельно в
каждой версии клиента. Для других клиентов generic — контракт адаптации, а не
объявление проверенной поддержки. Проверка файлов не подтверждает работу модели.

## Диагностика и проверка

Из исходного клона:

```bash
python3 scripts/panel_setup.py doctor --host codex --scope repo --project "/path/to/project"
python3 scripts/panel_setup.py doctor --host claude-code --scope repo --project "/path/to/project"
python3 -m unittest discover -s tests -v
```

Без подкоманды установщик выполняет `doctor`, не установку. `doctor` только читает
ожидаемые пути и маркеры; он не читает ключи/секреты, не меняет конфигурацию и не
доказывает наличие инструментов делегирования. После установки проверьте нужную
копию в каталоге навыков новой сессии и выполните [живые сценарии](reference/smoke-tests.md).
Запишите версию клиента и наблюдаемый результат; не отмечайте непроверенную среду как прошедшую.
