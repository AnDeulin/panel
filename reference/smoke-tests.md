# Проверка поведения в агентной среде

Выполняй после подключения в каждой заявленной среде отдельно. Наличие SKILL.md,
успех установщика и убедительное обещание ведущего не заменяют наблюдение.
Используй изолированный проект и вымышленные данные. Записывай версию клиента,
дату, источник загруженной копии panel, доступные возможности и реальные результаты.
Внешние сообщения, публикации и платные интеграции для этих сценариев не нужны.

| Сценарий / пример запроса | Что наблюдать |
| --- | --- |
| Простой: «Замени в этой строке “среда” на “четверг”» | Прямая правка; без панели, справочников и агентов. |
| Явный quick: «panel quick: проверь этот короткий план на слабые места» | Один агент; критическая проверка с начала, честный краткий вывод, без заявления независимой экспертизы. |
| Новая сложная цель: «Спроектируй систему обработки обращений небольшой организации» | Сначала цель и существенные вопросы. В full отдельный критик проверяет рамку сразу, без широкого исследования до цели. Затем требования → план → реализация в согласованном объёме. |
| Full с уже согласованными целью, требованиями и планом | Реальные отдельные предметные агенты и критик; получены результаты, первые позиции до обмена ответами, затем только существенные возражения и вердикт. Повторного разрешения на одобренную работу нет. |
| Сложный подвопрос в середине: после согласования локальной системы спросить о выборе хранения и восстановлении данных | Новая оценка риска и нужные роли; прежние ограничения сохранены, цель целиком заново не согласуется. |
| Продолжение: «Продолжай по согласованному плану»; затем новая цель «Теперь нужна стратегия другого проекта» | Продолжение не перезапускает процесс; действительно новая сложная цель уточняется отдельно, переносятся только применимые договорённости. |
| Новая поправка и конфликт: прежнее «можно внешний сервис» заменено «только локально» | Последняя поправка применяется, старое решение отмечено заменённым, рекомендуемый вариант соответствует текущим требованиям. |
| Сокращение истории / новый чат с паспортом и исходниками | Работа восстанавливается по паспорту; нужные источники дочитываются, недоступное явно названо, чужая история не выдумывается. |
| Делегирование недоступно, лимит параллелизма или ошибка роли | При лимите роли работают очередью; без делегирования full не имитируется. Ошибка/недостающий отчёт видны; нет выдуманного согласия. |
| Обоснованное согласие и существенное расхождение | Согласие допустимо после проверки. Реальное возражение проверено или осталось явной неопределённостью; большинство голосов само по себе не основание вердикта. |
| Запрос подробностей после краткого вердикта | Показаны реальные сохранённые заключения/источники, а не сочинённая ретроспектива спора. |

Сравни quick и full на нескольких характерных задачах пользователя: найденные
существенные ошибки, полезность решения, время и доступные измерения расхода.
Не оценивай качество по числу ролей, объёму текста или наличию обязательного спора.
Отдельно отметь непроверенные сценарии и ограничения среды. Числовую экономию без
измерений не заявляй.
